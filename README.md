# HopeTDL Prototype

这是一个 `tdl` 图形化操作原型，基于 Electron + Vue 3 + Element Plus。

## 当前功能

- 检测 `tdl version`
- 二维码 / 验证码 / Desktop 登录入口
- 对话列表 `tdl chat ls`
- 导出消息 `tdl chat export`
- 转发消息 `tdl forward`
- 上传文件 `tdl upload`
- 全局设置：`ns`、`proxy`、`delay`、`limit`、`threads`、`tdlPath`
- 命令预览
- 实时任务日志

## 安装依赖

```bash
npm install
```

## 启动开发版

```bash
npm run dev
```

## 使用前准备

确保系统已经安装 `tdl`，终端可执行：

```bash
tdl version
```

如果命令不在 PATH，可在软件「设置」里把 `tdl 路径`改成完整路径。

## 建议配置

国内环境可以在「设置」里填写代理：

```text
socks5://127.0.0.1:7890
```

命名空间建议使用你当前已经登录的：

```text
hope
```

## 注意

转发页面默认开启 `dry-run`，只演练不真正发送。确认命令没问题后，再取消勾选正式转发。

## v0.2.0：评论区顺序转发 + 关键词屏蔽

本版在左侧新增“评论区转发”页面，用于按以下顺序处理 Telegram 频道帖子：

```text
主消息 1 → 主消息 1 的评论区 → 主消息 2 → 主消息 2 的评论区 ...
```

支持功能：

- 源频道 / 群组选择；
- 起始消息 ID / 结束消息 ID；
- 目标 Peer；
- 目标 Thread / 话题 ID；
- 使用设置里的 tdl 路径、ns 命名空间、代理、limit、threads、delay；
- Windows 下目标话题自动使用 `target_router.txt`，避免 `{ Peer: "...", Thread: ... }` 被引号拆坏；
- 主消息和评论区关键词屏蔽；
- 关键词支持普通文本、可选区分大小写、可选正则；
- 主消息命中关键词时可选择连同评论区一起跳过；
- 仅导出不转发；
- 演练模式；
- progress.json 续跑；
- 已有缓存 JSON 跳过导出。

建议测试流程：

1. 先选择源频道，填写单条范围，例如 `2313 - 2313`；
2. 开启“演练模式”，确认主消息列表可导出；
3. 取消演练，勾选“仅导出不转发”，检查 `filtered` 目录里的关键词过滤结果；
4. 确认无误后取消“仅导出不转发”，正式转发。

## MSG_ID_INVALID 说明

如果日志出现：

```text
rpc error code 400: MSG_ID_INVALID
```

并且你填写了“目标话题 ID”，通常不是源消息问题，而是目标话题参数问题：

```text
1. 目标话题 ID 填错；
2. 目标群不是论坛 Topics 群；
3. 填的是话题内普通消息 ID，而不是话题根消息 ID；
4. 目标 Peer 不是实际的论坛群；
5. 当前账号没有在该话题发言权限。
```

新版增加：

```text
目标话题失败时降级到群默认聊天
```

开启后，如果往指定话题转发失败，会自动改成发到目标群默认聊天，避免整条任务中断。

手动验证话题 ID：

```bash
tdl -n hope forward --from post_936.json --to target_router.txt --mode direct
```

其中 `target_router.txt` 内容类似：

```text
{ Peer: "2365112217", Thread: 68549 }
```

如果仍然 `MSG_ID_INVALID`，说明 Thread=68549 不可用，需要重新从目标论坛群的话题链接里取根 ID。

## 无评论区时跳过主消息

新增开关：

```text
无评论区时跳过主消息
```

开启后执行顺序：

```text
1. 导出主消息
2. 导出该主消息的评论区
3. 如果评论区数量为 0，整组跳过，主消息也不转发
4. 如果评论区数量 > 0，先转发主消息，再转发评论区
```

如果同时启用了关键词屏蔽，则以“过滤后的评论区数量”为准。

例如：

```text
评论区原本有内容，但全部命中关键词被过滤掉
```

这种情况也会被视为“无评论区”，主消息同样不会转发。
